# 02 — ドメインモデル

ビジネスが思考の対象とする概念と、それらがどのように保存されるかに関わらず
成立するルールです。

## エンティティの全体像

```
Session ──owns──▶ Basket ──contains──▶ Line item ──refers to──▶ Product
   │                                                               │
   └──places──▶ Order ──contains──▶ Line item (frozen copy)        │
                  │                                          Rating (1:1)
                  └──produces──▶ Audit record
```

## Product（商品）

販売可能な単一の品目です。

| フィールド | 型 | ルール |
|---|---|---|
| `id` | 識別子 | システムが採番し、再利用されない |
| `name` | テキスト | 必須。顧客に表示される |
| `description` | テキスト | 任意 |
| `price` | 金額 | 必須。ゼロより大きい。セント単位の整数 |
| `imageUrl` | URL | 任意 |
| `stock` | 整数 | 必須。**決してマイナスにならない。** ゼロは売り切れを意味する |

在庫がゼロの商品は表示され続けますが、カートに追加することはできません。

価格は **金額（money）** 値です。常にセント単位の整数としてのみ扱われます。
商品はバージョン管理されません。価格を変更すると、すでに注文上に取り込まれて
いる箇所を除き、あらゆる箇所でその価格が変わります。

## Rating（評価）

1つの商品に対する集計スコアです。商品ごとに1件の評価レコードを持ちます。

| フィールド | 型 | ルール |
|---|---|---|
| `productId` | 識別子 | 対象の商品を識別する。商品ごとに評価は1件 |
| `value` | 小数 | 平均スコア。1.0〜5.0、小数第1位まで |
| `count` | 整数 | 集計に寄与した個別評価の件数。ゼロ以上 |

評価レコードを持たない商品は、ゼロとしてではなく、スコアなしで表示されます。

## Session（セッション）

匿名の訪問者としての識別情報です。

| フィールド | 型 | ルール |
|---|---|---|
| `id` | 識別子 | 初回訪問時に作成され、その訪問のあいだ不変 |
| `expiresAt` | タイムスタンプ | セッションが有効でなくなる時刻 |

セッションは個人データを一切保持しません。セッションはどのカートが誰のものかを
識別するだけであり、それ以上の役割はありません。期限切れのセッションは、明確に
識別可能な独立した状態です。セッションを一度も持たなかった状態とは同じでは
ありません。

## Basket（カート）

買い物客が選択済みでまだ支払っていない商品です。セッションごとに1つのカートを
持ちます。

| フィールド | 型 | ルール |
|---|---|---|
| `sessionId` | 識別子 | 所有するセッション |
| `items` | 明細行のリスト | 空でもよい |
| `updatedAt` | タイムスタンプ | カートが最後に変更された時刻 |

カートは **共有状態** です。同一のセッションが複数のブラウザタブやデバイスで
開かれている可能性があり、そのすべてが同じカートに対して操作を行います。同時
発生した変更は必ず調停されなければならず、暗黙に破棄されてはなりません。

カートは作業中の状態であり、記録ではありません。注文が実行された時点で空に
してかまいません。

### 明細行（カート内）

| フィールド | 型 | ルール |
|---|---|---|
| `productId` | 識別子 | 実在する商品を参照していること |
| `quantity` | 整数 | **ゼロより大きいこと。** ゼロもマイナスも不可 |

すでにカートに入っている商品を追加した場合は、同じ商品に対して2つ目の明細行を
作成するのではなく、その明細行の数量を増やします。

## Order（注文）

確定した購入です。作成後は **不変** です。

| フィールド | 型 | ルール |
|---|---|---|
| `id` | 識別子 | システムが採番する |
| `sessionId` | 識別子 | 誰が注文したか |
| `items` | 明細行のリスト | 購入時点の価格を含む凍結されたコピー |
| `subtotal` | 金額 | クーポン適用前の明細金額の合計 |
| `discountCodes` | テキストのリスト | 適用されたコード。適用された順に並ぶ |
| `total` | 金額 | クーポン適用後の請求額。決してマイナスにならない |
| `idempotencyKey` | テキスト | この注文の元となった購入意図を識別する |
| `status` | 列挙 | 下記のライフサイクルを参照 |
| `createdAt` | タイムスタンプ | 確定した時刻 |

注文上の明細行は参照ではなく **凍結されたコピー** です。後からの価格変更が、
過去の注文に記録された顧客の支払額を書き換えることは決してあってはなりません。

### 注文のライフサイクル

```
   pending ──────▶ confirmed
      │
      └──────────▶ failed
```

| ステータス | 意味 |
|---|---|
| `pending` | 処理中。まだ顧客への約束ではない |
| `confirmed` | 受理済み。在庫が確定され、顧客に成功したと伝えられている |
| `failed` | 完了しなかった。在庫は確定されず、請求もなく、顧客に失敗したと伝えられている |

`confirmed` および `failed` から抜け出す経路はありません。いずれも最終状態です。
注文が部分的に確定することはありません。すべての明細行が成功するか、注文全体が
失敗するかのいずれかです。

## Audit record（監査レコード）

照合のために保持される、注文の恒久的な記録です。

| フィールド | 型 | ルール |
|---|---|---|
| `orderId` | 識別子 | 対象となる注文 |
| `sessionId` | 識別子 | 誰が注文したか |
| `items` | 明細行のリスト | 請求された内容のとおり |
| `total` | 金額 | 請求された金額のとおり |
| `createdAt` | タイムスタンプ | 書き込まれた時刻 |

確定した注文ごとに監査レコードは1件、例外はありません。ライトワンス（一度だけ
書き込む）であり、変更も削除も決して行いません。

## 金額（Money）

本仕様におけるすべての金額は、同一のルールに従います。

- **セント** 単位の整数として保持する。小数値として保持しない
- 演算は厳密である。いかなる結果も浮動小数点表現に依存してはならない
- 丸めは計算の最後に **1回だけ** 行い、途中段階では決して行わない
- 表示は小数第2位までちょうどで行う
- 顧客に表示される金額と注文に記録される金額は、常に同一の数値である

## 不変条件（インバリアント）

以下はあらゆる時点で、すべてのコードパスにおいて成立します。

| # | 不変条件 |
|---|---|
| INV-1 | `Product.stock` は決してマイナスにならない |
| INV-2 | カート明細行の数量は、常にゼロより大きい整数である |
| INV-3 | 注文の `total` は、その `subtotal` から適用されたクーポン額を差し引いた値に等しく、決してマイナスにならない |
| INV-4 | 1つの `idempotencyKey` は、高々1件の注文にしか対応しない |
| INV-5 | すべての `confirmed` 注文は、ちょうど1件の監査レコードを持つ |
| INV-6 | 注文の明細金額の合計は、セント単位まで `subtotal` に等しい |
| INV-7 | 注文の明細行は、作成後に決して変化しない |
