# 01 — プロダクト概要

## ビジョン

QuickCart は小規模なオンラインストアフロントです。訪問者が来訪し、物販商品の
カタログを閲覧し、カートに商品を入れ、必要に応じてクーポンコードを適用し、
支払いを行います。アカウント作成のステップはなく、支払い方法の保存もありません。
着地から注文確定までを可能な限り最短の経路でつなぎます。

本プロダクトは、顧客がその経路を「本当に処理されたのだろうか」と不安に思うこと
なく完了できたときに成功と言えます。すなわち、表示された価格がそのまま支払う
価格であり、購入した商品が実際に在庫としてあり、ボタンを2回押しても2回分の
費用が発生しないことです。

## 利用者

| ペルソナ | 説明 | 必要とすること |
|---|---|---|
| **買い物客** | 匿名の訪問者。検索やリンクから来訪する。サインインはしない。 | 何が販売されていて価格がいくらかを把握し、1分以内に購入し、いくら請求されたのかを確信できること。 |
| **店舗運営者** | 店舗を日々運営する。 | 在庫数が実態を反映していること、およびすべての注文に記録があることを信頼できること。 |
| **サポート担当** | 「二重に請求された」「注文が消えた」といった問い合わせに対応する。 | 任意の注文について、何がいつ起きたのかを正確に再構成できること。 |
| **経理 / 監査** | 定期的に売上を照合する。 | すべての注文について、顧客への請求額と一致する、完全かつ不変の記録があること。 |

## スコープ

### スコープ内

- 価格・在庫数・評価を含む商品カタログの閲覧
- 訪問中の画面遷移をまたいで保持されるカート
- 数量の変更と商品の削除
- クーポンコード（複数併用を含む）
- 注文の実行と即時の確定通知
- すべての注文の監査用記録

### スコープ外

- 実際の決済処理 — 資金の移動を伴わずに注文が確定します
- 配送、フルフィルメント、配送追跡
- 返品と返金
- 顧客アカウント、注文履歴、住所の保存
- 多通貨対応。すべての金額は USD です
- 税額計算
- 在庫補充のワークフロー

## 「完成」の定義

| 目標 | 測定基準 |
|---|---|
| 顧客が価格を信頼できる | 支払い前に表示された合計金額が、注文に記録される金額とセント単位まで、常に一致する |
| 顧客が二重に請求されない | 1つの顧客の購入意図からは、ボタンを何回押しても、ちょうど1件の注文だけが生成される |
| 在庫が正直である | カタログが提供できない商品を決して販売対象として提示せず、在庫がマイナスにならない |
| 何も暗黙に失われない | 完了できなかった操作は、成功したように見せるのではなく、顧客にその旨を伝える |
| 問題が可視化される | すべての失敗は、顧客からの報告を待たずに、何が起きたのかを説明できる十分な詳細とともに記録される |

## 用語集

| 用語 | 意味 |
|---|---|
| **セッション** | 匿名の訪問者としての識別情報。訪問中のあいだ保持されます。どのカートが誰のものかを識別するためのもので、個人データは一切紐づきません。 |
| **カタログ** | 販売中の商品の一覧。現在の価格・在庫・評価を含みます。 |
| **商品** | 販売可能な単一の品目。名称、説明、価格、画像、在庫数を持ちます。 |
| **在庫** | 現在販売可能な数量。 |
| **評価** | 商品に対する顧客スコアの集計値。平均値と、その基となった評価件数から成ります。 |
| **カート**（basket） | 買い物客が選択済みでまだ支払っていない商品の集合。商品ごとに数量を持ちます。 |
| **明細行** | カートまたは注文における、1つの商品とその数量の組。 |
| **明細金額** | 単一の明細行における 単価 × 数量。 |
| **小計** | クーポン適用前の、すべての明細金額の合計。 |
| **クーポンコード** | チェックアウト時に入力することで支払額を減額するコード。 |
| **注文合計** | クーポン適用後に顧客へ請求される最終金額。 |
| **注文** | 確定した購入。作成後は不変です。 |
| **冪等キー**（idempotency key） | 1つの購入意図を識別する値。同一の意図が繰り返し送信されても、複数の注文が作成されないようにします。 |
| **監査レコード** | すべての注文に対して書き込まれる恒久的な記録。照合に使用されます。 |
| **配送料見積** | チェックアウト中に配送業者から取得する配送費用の見積り。 |
